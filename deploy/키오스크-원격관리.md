# 키오스크 원격 관리 가이드

맥에서 키오스크 PC를 원격으로 접속·시작·종료·업데이트하는 방법을 정리한 문서입니다.
명령은 따로 표시가 없으면 **맥 터미널**에서 실행합니다.

최종 확인/작성: 2026-11-04

## 2. 맥 쪽 사전 설정 (이미 돼 있음)

`~/.ssh/config` 에 아래 별칭이 설정돼 있어 `ssh kiosk` 한 번으로 접속됩니다.
다른 맥/PC에서 접속하려면 같은 설정과 개인키(`id_ed25519_sjiot`)가 필요합니다.

```
Host kiosk
  HostName 192.168.0.11
  User kioskadmin
  IdentityFile ~/.ssh/id_ed25519_sjiot
  IdentitiesOnly yes
  StrictHostKeyChecking accept-new
```

접속 확인:

```bash
ssh kiosk whoami
```

`desktop-hlvsdtt\kioskadmin` 이 나오면 정상입니다.

> 참고: 콘솔 로그인 계정인 한글 Azure AD 계정(`azuread\안원지`)으로는 SSH가 안 됩니다
> (윈도우 SSH 서버가 한글 사용자명을 유효 계정으로 인식하지 못함). 원격 접속은 항상 `kioskadmin`을 씁니다.

## 3. 재부팅 후 원격 접속

- SSH 서버(`sshd`)는 **자동 시작(Automatic)** 으로 설정돼 있습니다. 그래서 키오스크 PC를 재부팅하면
  **윈도우 로그인 전에도** SSH가 떠서, 맥에서 `ssh kiosk ...` 가 바로 됩니다. 별도 조작이 필요 없습니다.

```bash
ssh kiosk whoami
```

- 단, **자동 로그인은 꺼져 있습니다.** 그래서 재부팅 후 **앱 화면**이 키오스크 모니터에 뜨려면
  누군가 키오스크에서 **안원지 계정으로 윈도우 로그인**을 해야 합니다. 로그인하면 예약 작업(`SJIOT-Kiosk`)이
  앱을 자동으로 띄웁니다.

> 요약: 재부팅 → SSH는 바로 됨(사람 개입 불필요) / 앱 화면은 안원지로 로그인해야 뜸.
> 사람 없이 재부팅만으로 앱까지 자동으로 띄우고 싶으면 "6. 선택: 무인 자동 시작" 참고.

## 4. 원격 시작 / 종료

### 앱 시작

```bash
ssh kiosk "powershell -NoProfile -Command Start-ScheduledTask -TaskName SJIOT-Kiosk"
```

- 예약 작업이 **안원지 세션**에서 앱을 실행하므로, 안원지가 로그인돼 있어야 모니터 화면에 뜹니다.
  로그인돼 있지 않으면 화면에는 안 뜹니다(로그인 시 자동 실행됨).

### 앱 종료

```bash
ssh kiosk "powershell -NoProfile -Command Stop-Process -Name clicky_keyring -Force"
```

### 앱 재시작 (종료 후 시작)

```bash
ssh kiosk "powershell -NoProfile -Command Stop-Process -Name clicky_keyring -Force; Start-ScheduledTask -TaskName SJIOT-Kiosk"
```

### 실행 여부 확인

```bash
ssh kiosk "powershell -NoProfile -Command (Get-Process clicky_keyring -ErrorAction SilentlyContinue | Measure-Object).Count"
```

`1` 이상이면 실행 중입니다.

## 5. 원격 업데이트

업데이트 스크립트는 GitHub **최신 정식 릴리즈**(태그 `v*`)의 zip을 받아 설치 폴더를 통째로 교체하고 앱을 다시 켭니다.
실패하면 직전 버전(`C:\SJIOT\kiosk.bak`)으로 자동 복구합니다.

### 5-1. 코드 변경이 없을 때 (최신 릴리즈 재설치)

```bash
ssh kiosk "powershell -ExecutionPolicy Bypass -File C:\SJIOT\update-kiosk.ps1"
```

출력에 `[1/5] … [5/5] … 완료: SJIOT-kiosk-windows-vX.Y.Z-xxxx.zip` 이 나오면 성공입니다.

### 5-2. 코드를 바꿨을 때 (예: 서버 주소 변경) — 새 릴리즈부터 만들어야 함

> 중요: 서버 주소(`lib/services/api_service.dart` 의 `ApiService.baseUrl`) 같은 설정은
> **빌드 시점 코드로 컴파일**됩니다. 코드만 고치고 릴리즈를 안 만들면 키오스크에는 반영되지 않습니다.
> 원격 업데이트는 항상 "최신 정식 릴리즈"를 받으므로, 바꾼 코드로 새 `v*` 태그를 만들어야 합니다.

1. 코드 커밋 후 원격에 push (예: `front_kiosk` 브랜치).

2. 새 버전 태그를 달아 push → GitHub Actions가 윈도우 빌드를 돌리고 릴리즈에 zip을 첨부합니다.

```bash
git tag -a v1.0.2 -m "변경 내용 요약"
git push origin v1.0.2
```

3. 빌드가 끝날 때까지 대기(보통 4~5분).

```bash
gh run watch $(gh run list --workflow build-windows.yml --limit 1 --json databaseId --jq '.[0].databaseId') --exit-status
```

4. 릴리즈에 zip이 올라왔는지 확인.

```bash
gh release view v1.0.2 --repo sjiot/platform-kiosk-front --json tagName,assets --jq '.tagName, (.assets[].name)'
```

5. 키오스크 원격 업데이트 실행.

```bash
ssh kiosk "powershell -ExecutionPolicy Bypass -File C:\SJIOT\update-kiosk.ps1"
```

6. 배포된 바이너리에 새 설정이 들어갔는지 확인(예: 서버 주소).

```bash
ssh kiosk "powershell -NoProfile -Command \$b=[IO.File]::ReadAllBytes('C:\SJIOT\kiosk\data\app.so'); [Text.Encoding]::ASCII.GetString(\$b).Contains('192.168.0.100:5000')"
```

`True` 가 나오면 반영된 것입니다.

## 6. 로그 확인

앱은 시작/생존 신호/에러를 파일 로그로 남깁니다. 마지막 50줄 보기:

```bash
ssh kiosk "powershell -NoProfile -Command Get-Content (Resolve-Path 'C:\Users\*\AppData\Local\ClickyKeyring\logs\app.log') -Tail 50 -Encoding utf8"
```

로그 파일을 맥으로 가져오기:

```bash
scp kiosk:'C:/Users/안원지/AppData/Local/ClickyKeyring/logs/app.log' ~/Desktop/kiosk-app.log
```

## 7. 롤백

- 업데이트가 실패하면 스크립트가 자동으로 `C:\SJIOT\kiosk.bak` 로 복구하고 앱을 다시 켭니다.
- 업데이트는 성공했는데 새 버전에 문제가 있어 직전 버전으로 되돌리려면(수동):

```bash
ssh kiosk "powershell -NoProfile -Command Stop-Process -Name clicky_keyring -Force; robocopy C:\SJIOT\kiosk.bak C:\SJIOT\kiosk /MIR; Start-ScheduledTask -TaskName SJIOT-Kiosk"
```

> `kiosk.bak` 은 **직전 1개 버전**만 보관합니다. 다음 업데이트 때 덮어써집니다.

## 8. 선택: 무인 자동 시작

사람이 로그인하지 않아도 재부팅만으로 앱까지 자동으로 뜨게 하려면, 키오스크 PC에서 **자동 로그인**을 켜야 합니다.
현재는 꺼져 있습니다(`AutoAdminLogon=0`). 자동 로그인은 비밀번호가 레지스트리에 저장되는 보안 트레이드오프가 있으니,
필요하면 별도로 설정해 주세요. (이 문서 범위 밖)

## 9. 자주 겪는 문제

| 증상 | 원인 / 조치 |
|---|---|
| "시작하기" 눌러도 반응 없음 | 앱의 `baseUrl` 이 옛 주소일 수 있음. 5-2로 새 릴리즈를 만들고 재배포. `app.so` 주소 확인. |
| 서버는 켜져 있는데 안 됨 | 서버 확인: `curl http://192.168.0.100:5000/queue/status` 가 200이면 서버는 정상. 문제는 앱 쪽. |
| 맥에서 SSH 안 됨 | 한글 Azure AD 계정 말고 `kioskadmin` 으로 접속하는지 확인. 재부팅 직후면 sshd(Automatic)가 뜰 때까지 잠깐 대기. |
| 앱이 모니터에 안 뜸 | 안원지로 윈도우 로그인이 돼 있는지 확인(자동 로그인 꺼짐). 로그인하면 예약 작업이 자동 실행. |
| 업데이트가 옛 버전을 받음 | 새 코드가 `v*` 태그로 릴리즈됐는지 확인. 릴리즈 안 하면 최신 정식 릴리즈(옛 버전)를 받음. |

## 10. 서버 빠른 점검 (맥에서)

```bash
curl -s -o /dev/null -w "%{http_code}\n" http://192.168.0.100:5000/queue/status
```

`200` 이면 서버 정상입니다.
